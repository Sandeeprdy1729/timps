Gmail Connector

Turn your inbox into a memory. One OAuth connect, then every synced email is distilled into knowledge facts your agent can recall forever.

Connect Gmail

One command connects your inbox — a browser consent screen opens, tokens land in ~/.timps/gmail/, and nothing touches any server.

timps gmail:connect   # opens Google consent, saves tokens locally
timps gmail:sync     # run a sync from the terminal

No app installed? Run timps gmail:connect after installing TIMPS, then sync anytime with timps gmail:sync.

Overview

The Gmail connector is a read-only integration. It never sends, drafts, or deletes anything.

  • Connect with a Google OAuth consent screen (Desktop / installed-app client)
  • Every sync scans the inbox and distills each email into 1–3 knowledge facts
  • Facts are stored in TIMPS long-term memory with tags email, gmail, knowledge, sender:<address>
  • Searchable with timps recall and in the desktop app
First sync backfills the inbox (capped for speed). Later syncs only pull mail newer than the last run. The raw emails stay in your local store — nothing is uploaded.

How it works

sync
Sync

Fetches new inbox mail with a refresh token, matches the previous run, and stores raw JSON per message.

distill
Distill

Summarizes each message — subject, sender, date, and the key facts worth remembering.

remember
Remember

Facts enter semantic memory and show up in timps recall and the memory graph.

Data store

Everything lives locally in ~/.timps/gmail/ — shared by the CLI, the desktop app, and the launchd job:

~/.timps/gmail/
├── client.json        # Google OAuth client id + secret (chmod 600)
├── tokens.json        # refresh + access tokens (chmod 600)
├── state.json         # lastRun, lastMessageId, messagesSynced
├── summaries.jsonl    # distilled facts (one JSON object per email)
└── raw/YYYY-MM-DD/    # raw per-message copies
    <id>.json
Tokens are local. Never committed, never leave your machine. The desktop app and CLI read summaries locally — nothing is uploaded.

CLI — sync now

timps gmail:sync           # one-shot sync from the terminal
timps gmail:recent 10      # show 10 latest distilled facts
timps gmail:search "aws"   # search facts by subject / sender / content

CLI — auto-sync (cron)

Register a daily job (09:00) with the built-in cron helper:

timps gmail:cron           # install the daily sync job
timps gmail:cron --remove # remove it

On macOS this installs a launchd agent (ai.timps.gmail.sync). Logs land in ~/.timps/gmail/logs/.

Desktop app — Connectors tab

  • Open Connectors in the sidebar, then Connect — the consent screen opens in your browser and the desktop app completes OAuth locally
  • Import credentials points at a downloaded Google client JSON (no secrets cross the renderer)
  • Sync now runs the same pipeline as the CLI
  • Auto-sync installs/removes the daily job
  • Search filters the distilled email memories right in the tab
Network-free renderer. The desktop OAuth flow runs entirely in Rust — the renderer stays network-free so the app CSP stays locked.

Chat commands

Type these in the desktop Chat to query the inbox without an LLM round-trip:

CommandWhat it does
/email recent 5Latest distilled email memories
/email search <query>Search by subject, sender, or fact
/email syncRun a sync from chat

Privacy

  • Read-only scopes only — no send, draft, or delete permissions
  • Raw copies and tokens stay on your machine
  • Only distilled facts (subject + sender + key facts) enter the memory store you control
  • Disconnect anytime with timps gmail:reset or the app's Disconnect button
